PingInfo 项目 Bug 清单
========================================
项目地址: https://github.com/ziyiliunian/pinginfo
技术栈: Python 3.8+ / PyQt5
整理日期: 2026-08-24

严重程度说明:
  [崩溃]   会导致程序崩溃或异常退出
  [数据错乱] 产生错误的结果或操作到错误对象
  [内存/卡死] 内存耗尽或界面长时间无响应
  [静默丢目标] 无提示地丢失用户数据
  [生命周期] 线程/资源生命周期管理缺陷
  [输出注入] 输出内容存在注入或转义风险
  [图标/打包] 打包与资源路径问题
  [健壮性] 代码健壮性与冗余问题
  [语义] 参数含义与实现不一致

========================================
一、[崩溃] 中文 Windows 下 RTT 解析失败导致 TypeError
----------------------------------------
位置: ping_core.py 的 _parse_ping_output() -> data_models.py 的 update_success()
问题描述:
  中文 Windows 的 ping 输出为「时间=10ms」，但 RTT 提取正则只匹配英文
  "time"，导致结果 success=True 但 rtt=None。随后 update_success() 中
  执行 sum_rtt += None，抛出 TypeError，首次成功 ping 即崩溃。
建议修复:
  1. 增加中文 RTT/TTL 正则，如: 时间[=<]?([\d.]+)
  2. 或当 rtt 为 None 时按失败/跳过处理，避免 None 参与算术运算

========================================
二、[数据错乱] 表格排序后行号与目标索引错位
----------------------------------------
位置: main_window.py 的 delete_selected() / toggle_selected() /
      _on_item_changed() / export_results()
问题描述:
  表格启用排序后，selectedIndexes() 返回的 idx.row() 是视觉行号，但代码
  直接将其当作 self.targets 列表索引使用，导致删除、启用/禁用、勾选、
  导出选中行时操作到错误的目标。
建议修复:
  1. 在 QTableWidgetItem 的 Qt.UserRole 中存储目标对象或索引
  2. 或通过 verticalHeader().logicalIndex() 将视觉行号映射回逻辑行号

========================================
三、[内存/卡死] CIDR 展开无规模上限
----------------------------------------
位置: ping_core.py 的 expand_ip_range()
问题描述:
  CIDR 分支没有数量上限，输入 10.0.0.0/8、0.0.0.0/0 等会展开成千万级
  IP 列表，导致内存耗尽、界面卡死。注: '-' 范围分支有 65535 上限，
  CIDR 分支却没有。
建议修复:
  对 CIDR 展开同样加数量上限，超限时弹窗警告或拒绝展开

========================================
四、[静默丢目标] 去重键不含端口
----------------------------------------
位置: main_window.py 的 add_targets()
问题描述:
  去重键为 (address, ping_mode)，不包含端口。同一主机不同 TCP 端口
  (如 host:80 与 host:443) 会被静默丢弃其中一个。
建议修复:
  去重键加入 tcp_port，改为 (address, ping_mode, tcp_port)

========================================
五、[界面卡死] 域名解析阻塞主线程
----------------------------------------
位置: main_window.py 的 _resolve_targets_async()
问题描述:
  线程池执行 DNS 解析，但 as_completed 循环在主线程阻塞等待全部完成；
  且 resolve_to_ipv4() 的 timeout 参数是死代码，getaddrinfo 实际无超时，
  慢 DNS 会导致界面长时间无响应。
建议修复:
  1. 使用 QThread/信号异步回填结果
  2. 或给 DNS 解析加真实超时(将 getaddrinfo 放入线程并限制等待时间)

========================================
六、[界面卡死] MAC 查询阻塞主线程
----------------------------------------
位置: main_window.py 的 query_mac_addresses()
问题描述:
  在 GUI 线程逐个执行子进程(每个最多 3 秒)，目标数量多时界面长时间
  无响应。
建议修复:
  放入后台线程/线程池执行，结果回填后刷新表格

========================================
七、[生命周期] 停止监控后旧线程仍运行
----------------------------------------
位置: main_window.py 的 stop_monitoring() / closeEvent()
问题描述:
  wait(5000) 超时后直接 self.worker = None，旧线程仍在运行(单批 ICMP
  最长可达 timeout+5 秒)，其 batch_complete 信号仍会更新表格；退出时
  可能出现「QThread 运行中被销毁」。
建议修复:
  1. 让批次可中断(事件/超时)
  2. 停止后断开信号连接并真正等待线程结束

========================================
八、[输出注入] HTML 导出未转义特殊字符
----------------------------------------
位置: exporters.py 的 export_html()
问题描述:
  HTML 使用字符串拼接，未转义 < > & 等特殊字符，错误信息等若包含
  特殊字符会破坏页面结构。
建议修复:
  使用 html.escape() 转义单元格值

========================================
九、[图标/打包] 图标回退路径错误 + Installed-Size 统计不全
----------------------------------------
位置: main.py 的 _load_app_icon() / build.sh
问题描述:
  1. 回退路径写的是 /opt/pinginfo/usr/share/...，而 build.sh 实际将图标
     安装到 /usr/share/icons/...，回退路径错误
  2. build.sh 的 Installed-Size 只统计 /opt，未计入 /usr 目录
建议修复:
  1. 修正图标回退路径
  2. Installed-Size 统计整个 pkgroot

========================================
十、[健壮性] tcp_ping 双 close + 异常捕获冗余
----------------------------------------
位置: ping_core.py 的 tcp_ping() / resolve_to_ipv4()
问题描述:
  1. tcp_ping() 中存在两次 sock.close() 调用
  2. resolve_to_ipv4() 的 except (..., Exception) 元组冗余，
     Exception 已覆盖其余异常类型
建议修复:
  1. 关闭后将 sock 置为 None
  2. 精简异常捕获列表

========================================
十一、[语义] packet_size=0 语义不一致
----------------------------------------
位置: dialogs.py 的 SettingsDialog
问题描述:
  packet_size=0 提示为「系统默认」，但代码在 != 56 时仍会传 -s 0/-l 0，
  实际含义是 0 字节而非默认值。
建议修复:
  对 0 做特判，跳过该参数

========================================
其他改进建议
----------------------------------------
1. 缺少测试与 CI: expand_ip_range、_parse_ping_output 等纯函数适合用
   pytest 覆盖
2. is_running 语义过载: 同一字段既表示「是否启用」又驱动 status_text，
   建议拆分为 enabled 与运行状态
3. host:port 解析重复: dialogs.py、_load_file()、dropEvent() 三处重复，
   应抽取公共函数
4. 版本不一致: __init__.py/control 为 1.1.1，README/build.sh 为 1.1.0；
   control 的 Homepage 仍为占位符
5. 无配置持久化: 间隔/并发数/超时等设置重启即丢失，可用 QSettings 保存
6. 跨平台一致性: 可考虑用 ping3 等原生库替代系统 ping 子进程，减少进程
   开销并统一解析逻辑
