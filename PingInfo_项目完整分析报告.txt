######################################################################
#  项目概述
######################################################################
PingInfo 是一款仿 PingInfoView 的批量 Ping 实时监控工具，支持
ICMP 与 TCP Ping、IPv4/IPv6、批量目标管理、实时统计和
TXT/CSV/HTML/XML 导出，并提供 Debian .deb 打包。

模块结构:
  src/ping_core.py    — Ping 核心模块（ICMP/TCP Ping、IP 范围展开、域名解析）
  src/data_models.py  — 数据模型（TargetStats 统计与状态）
  src/main_window.py  — 主窗口（表格、监控线程、后台任务）
  src/dialogs.py      — 对话框（添加目标、设置、导出选择）
  src/exporters.py    — 结果导出（TXT/CSV/HTML/XML）
  src/arp_lookup.py   — MAC 地址查询（ip neigh / arp -n）
  src/main.py         — 程序入口与图标加载
  build.sh            — Debian deb 打包脚本

优点:
  - 模块化清晰，核心逻辑、数据模型、导出、UI 职责分离
  - ThreadPoolExecutor 批量并发 Ping，域名解析异步化
  - 表格性能优化：NumericTableWidgetItem 按真实数值排序、增量更新单元格
  - 功能丰富：IP 范围/CIDR 展开、TCP 带端口、拖放导入、右键菜单、快捷键
  - 中文本地化友好；Debian 打包规范完整

#  第一部分：v1.1.1 原始 Bug 清单（11 项）

========================================
历史 Bug #1  [崩溃] 中文 Windows 下 RTT 解析失败导致 TypeError
========================================
位置: ping_core.py _parse_ping_output() → data_models.py update_success()
问题: 中文 Windows 的 ping 输出为「时间=10ms」，但 RTT 提取正则只匹配
      英文 "time"，导致 success=True 但 rtt=None，随后 sum_rtt += None
      抛出 TypeError，首次成功 ping 即崩溃。
修复: v1.1.2 增加中文 RTT/TTL 正则，rtt 为 None 时仅计数不参与运算。 ✅

========================================
历史 Bug #2  [数据错乱] 表格排序后行号与目标索引错位
========================================
位置: main_window.py delete_selected() / toggle_selected() /
      _on_item_changed() / export_results()
问题: 表格启用排序后 idx.row() 是视觉行号，却被直接当作 self.targets
      列表索引，导致删除、启停、勾选、导出选中行时操作到错误目标。
修复: v1.1.2 在 Qt.UserRole 中存储目标对象，按对象身份映射。 ✅

========================================
历史 Bug #3  [内存/卡死] CIDR 展开无规模上限
========================================
位置: ping_core.py expand_ip_range()
问题: CIDR 分支没有数量上限，10.0.0.0/8、0.0.0.0/0 等会展开成千万级
      IP 列表，导致内存耗尽、界面卡死。
修复: v1.1.2 对 CIDR 展开增加 65535 数量上限。 ✅

========================================
历史 Bug #4  [静默丢目标] 去重键不含端口
========================================
位置: main_window.py add_targets()
问题: 去重键为 (address, ping_mode)，不含端口，同一主机不同 TCP 端口
      (如 host:80 与 host:443) 会被静默丢弃其中一个。
修复: v1.1.2 去重键加入 tcp_port。 ✅

========================================
历史 Bug #5  [界面卡死] 域名解析阻塞主线程
========================================
位置: main_window.py _resolve_targets_async()
问题: 线程池执行 DNS 解析，但 as_completed 循环在主线程阻塞等待；
      resolve_to_ipv4() 的 timeout 参数是死代码，慢 DNS 卡死界面。
修复: v1.1.2 移至后台 ResolveWorker 线程，带 30 秒整体超时。 ✅

========================================
历史 Bug #6  [界面卡死] MAC 查询阻塞主线程
========================================
位置: main_window.py query_mac_addresses()
问题: 在 GUI 线程逐个执行子进程（每个最多 3 秒），目标多时界面无响应。
修复: v1.1.2 移至后台 MacWorker 线程。 ✅

========================================
历史 Bug #7  [生命周期] 停止监控后旧线程仍运行
========================================
位置: main_window.py stop_monitoring() / closeEvent()
问题: wait(5000) 超时后直接 self.worker = None，旧线程仍在运行，
      batch_complete 信号仍会更新表格；退出时可能「QThread 运行中被销毁」。
修复: v1.1.2 停止时断开旧线程信号，超时未结束的线程自动销毁。 ✅

========================================
历史 Bug #8  [输出注入] HTML 导出未转义特殊字符
========================================
位置: exporters.py export_html()
问题: HTML 用字符串拼接，未转义 < > & 等特殊字符，可能破坏页面结构。
修复: v1.1.2 使用 html.escape() 转义单元格值。 ✅

========================================
历史 Bug #9  [图标/打包] 图标回退路径错误 + Installed-Size 统计不全
========================================
位置: main.py _load_app_icon() / build.sh
问题: 回退路径写的 /opt/pinginfo/usr/share/... 与实际安装路径不符；
      build.sh 的 Installed-Size 只统计 /opt，未计入 /usr。
修复: v1.1.2 修正回退路径为 /usr/share/icons/...；统计 /opt 与 /usr。 ✅

========================================
历史 Bug #10 [健壮性] tcp_ping 双 close + 异常捕获冗余
========================================
位置: ping_core.py tcp_ping() / resolve_to_ipv4()
问题: tcp_ping() 存在两次 sock.close() 调用；resolve_to_ipv4() 的
      except (..., Exception) 元组冗余。
修复: v1.1.2 关闭后置 None 避免双 close；精简异常捕获。 ✅

========================================
历史 Bug #11 [语义] packet_size=0 语义不一致
========================================

========================================================================
【Bug #1】【高】【资源泄漏】监控中删除目标，已删目标仍在后台被 Ping
========================================================================
位置: main_window.py 第 457-464 行 delete_selected()
      main_window.py 第 492 行 start_monitoring()

根因:
  delete_selected() 用列表推导式重新赋值 self.targets：
    第 463 行: self.targets = [t for t in self.targets if id(t) not in to_delete]
  这创建了一个【新列表对象】，而 PingWorker 在 start_monitoring() 时
  持有的是【旧列表对象的引用】：
    第 492 行: self.worker = PingWorker(self.targets, ...)
    第 36 行:  self.targets = targets  # worker 存的是旧列表

  因此删除后，worker 的下一轮循环（第 47 行）仍遍历旧列表中的全部
  目标，包括已被用户删除的目标。

现象:
  1. 已删除目标持续消耗系统资源（每轮并发 ping 进程 + 网络）
  2. 用户感知不到——新列表已替换，表格已刷新，但后台仍 in-flight
  3. 反复"添加-删除"会累积幽灵目标，CPU/内存持续上升
  4. 只有用户手动 F6 停止监控才会真正停止

复现步骤:
  1. 添加 10 个目标 → F5 开始监控
  2. 选中 5 个目标 → Delete 删除
  3. 观察系统进程管理器：仍有 10 个 ping 进程并发执行
  4. F6 停止 → F5 重启 → 只剩 5 个（确认旧列表残留）

修复建议:
  改为 in-place 删除（切片赋值），worker 持有的列表对象不变：
    self.targets[:] = [t for t in self.targets if id(t) not in to_delete]
  这样 worker 下一轮循环立即看到删除后的列表。
  注意：GIL 保证切片赋值的原子性，worker 迭代时不会崩溃。

========================================================================
【Bug #2】【高】【退出崩溃】关闭窗口时未停止后台线程，可能段错误
========================================================================
位置: main_window.py 第 808-810 行 closeEvent()
      main_window.py 第 388-392 行 _start_bg_worker()

根因:
  closeEvent() 只调用了 stop_monitoring()（停止 PingWorker），
  但完全没有处理 _bg_workers 列表中的 ResolveWorker 和 MacWorker。

  这些后台 QThread 可能仍在运行（MacWorker 每个目标最多
  icmp_ping(6s) + get_mac_address(3s) ≈ 9 秒）。程序退出时：
  1. MainWindow 被 Python GC 回收 → _bg_workers 列表销毁
  2. QThread 对象失去引用，但线程仍在运行
  3. Qt 检测到 QThread 被销毁时线程仍在运行 → 打印警告并可能段错误

  典型报错:
    QThread: Destroyed while thread is still running
    QThread: Destroyed while threads are still running

触发条件:
  - 查询 MAC 地址后立即关闭窗口（MacWorker 可能仍在运行）
  - 添加域名目标后立即关闭窗口（ResolveWorker 可能仍在运行）

修复建议:
  closeEvent() 中遍历 _bg_workers，逐一请求中断并等待：
    for w in self._bg_workers[:]:
        w.quit()
        w.wait(3000)
    self._bg_workers.clear()
  更彻底的方案：给 ResolveWorker / MacWorker 增加 _stop 标志，
  让 run() 循环可中断。

========================================================================
【Bug #3】【中】【竞态崩溃】clear_all 在 stop_monitoring 超时后清空列表
========================================================================
位置: main_window.py 第 466-472 行 clear_all()
      main_window.py 第 500-515 行 stop_monitoring()

根因:
  clear_all() 调用 stop_monitoring()，后者 wait(5000) 超时后
  直接返回（第 510-512 行），PingWorker 线程仍在运行。
  随后第 470 行 self.targets.clear() 在主线程清空列表。

  如果此刻 worker 正在执行第 47 行：
    active = [t for t in self.targets if t.is_running]
  则列表在迭代过程中被清空 → Python 抛出:
    RuntimeError: list changed size during iteration

  虽然 _stop 已被置为 True，worker 会在当前批次结束后退出，
  但 clear() 可能在批次结束前执行（wait 超时即此场景）。

触发条件:
  - 大量目标（单批 ping 超过 5 秒未完成）
  - 此时点击"清空全部"→ 确认

修复建议:
  方案 A: clear_all 不调用 clear()，改为重新赋值（同 Bug #1），
         让 worker 持有旧列表自然结束。
  方案 B: stop_monitoring 超时后不继续操作，弹窗提示用户稍后重试。
  方案 C: 给 worker 增加可中断机制，确保 wait 能及时返回。

========================================================================
【Bug #4】【中】【视觉缺陷】禁用目标重新启用后，非状态列文字仍为灰色
========================================================================
位置: main_window.py 第 620-661 行 _set_row()

根因:
  _set_row() 第 657-661 行：当 is_running=False 时，将第 1~17 列
  的前景色全部设为 #999999（灰色）。
  但当 is_running=True 时，只有第 4 列（状态列）在第 638-643 行
  显式设置前景色；其余列通过 _c()/_nc() 只更新文本，不重置颜色。

  因此：禁用一行 → 启用该行 → 状态列恢复彩色，但地址、Ping方式、
  响应时间、TTL 等列仍显示灰色，看起来像仍被禁用。

修复建议:
  在 _set_row 的 is_running=True 分支中，显式恢复默认前景色：
    if s.is_running:
        default_color = QColor("#263238")
        for col in range(1, self.table.columnCount()):
            it = self.table.item(row, col)
            if it and col != 4:  # 第4列由下方逻辑单独处理
                it.setForeground(default_color)

========================================================================
【Bug #5】【中】【功能缺失】IPv6 + TCP 端口写法不支持
========================================================================
位置: dialogs.py 第 164 行 _accept()
      main_window.py 第 445 行 _load_file()
      main_window.py 第 797 行 dropEvent()

根因:
  三处用相同的逻辑判断 host:port：
    if ":" in line and line.count(":") == 1:
  IPv6 地址含有多个冒号（如 2001:db8::1），即使不带端口也有 >1 个
  冒号，因此 [2001:db8::1]:80 无法被正确解析。

  纯 IPv6 地址（如 ::1）虽然冒号数 != 1，会跳过端口解析进入
  expand_ip_range()，后者返回原样字符串，最终作为 ICMP 目标可以
  工作（ping ::1）。但 IPv6 + TCP 端口的组合完全无法使用，
  而 README 声称"支持 IPv6"。

修复建议:
  1. 支持 [ipv6]:port 方括号写法
  2. 用 ipaddress.ip_address() 先判断是 v4/v6/域名
  3. 将三处重复逻辑抽取为公共函数 parse_host_port()

========================================================================
【Bug #6】【低】【体验】refresh_table 每轮重新排序，用户排序后行持续跳动
========================================================================
位置: main_window.py 第 602-609 行 refresh_table()

现象:
  refresh_table() 在每轮批次完成时（on_batch_complete → 第 523 行）
  被调用。第 608 行 setSortingEnabled(True) 触发全表重新排序。
  如果用户已点击某列排序，则每隔 1 秒（默认间隔）所有行重新排序，
  用户正在查看的行会跳动，难以定位。

修复建议:
  排序状态未变化时跳过 setSortingEnabled(True)，或仅在用户手动
  触发排序时才启用，监控刷新时保持当前视觉顺序。

========================================================================
【Bug #7】【低】TCP ConnectionRefused 的 RTT 被丢弃
========================================================================
位置: ping_core.py 第 217-220 行 tcp_ping()
      main_window.py 第 522 行 on_batch_complete()
说明: tcp_ping 在连接被拒绝时计算了 RTT 并放入 PingResult，
      但 on_batch_complete 失败路径只传 error，不传 rtt。
      update_fail() 也直接将 last_rtt 置为 None（第 89 行）。
      主机可达但端口未开的有价值延迟数据被丢弃。
建议: update_fail() 增加可选 rtt 参数。

========================================================================
【Bug #8】【低】rtt_history 死代码
========================================================================
位置: data_models.py 第 26 行、第 81-83 行、第 92-94 行
说明: TargetStats 维护了最近 20 次 RTT 历史，但整个代码库中
      没有任何地方读取它。徒增内存（尤其目标数量多时）。
建议: 若计划做图表/抖动计算则保留并在后续版本使用，否则删除。

========================================================================
【Bug #9】【低】CSV 导出存在公式注入风险
========================================================================
位置: exporters.py 第 55-67 行 export_csv()
说明: CSV 直接写入用户可控的 address、last_error 等字段。如果某个
      值以 = + - @ 开头，在 Excel 中打开时可能被解释为公式。
      对于网络工具风险较低（地址一般不含这些字符），但 error 字段
      可能包含特殊字符。
建议: 对以 = + - @ 开头的单元格，前面加单引号前缀。

========================================================================
【Bug #10】【低】resolve_to_ipv4 的 timeout 参数是死代码
========================================================================
位置: ping_core.py 第 280 行 resolve_to_ipv4(address, timeout=2.0)
说明: timeout 参数在函数体内从未使用。socket.getaddrinfo 无超时
      控制。ResolveWorker 用 as_completed(timeout=30) 在整体层面
      超时，但单个慢 DNS 线程会一直阻塞到系统 DNS 超时（可能 30s+）。
      ex.shutdown(wait=False) 不等待这些线程，它们成为僵尸线程。
建议: 删除死参数，或用线程 + 事件实现真实超时。

========================================================================
【Bug #11】【低】"监控"列名与实际功能语义不符
========================================================================
位置: main_window.py 第 20 行 COLUMNS 第 0 列 "监控"
说明: 该列复选框控制的是 selected（导出选择），不是 is_running
      （监控启停）。列名"监控"会让用户以为勾选/取消即开始/停止
      对该目标的监控。tooltip 已说明"勾选后可按勾选范围导出"，
      但列名仍具误导性。
建议: 列名改为"导出"或"选择"。

#  第三部分：线程安全专项分析
######################################################################

共享对象            主线程操作            子线程操作          安全性
------------------  -------------------  ------------------  --------
self.targets 列表   append(添加目标)      迭代(worker第47行)  ⚠️ 竞态
                    =(delete_selected)                        ⚠️ 见Bug#1
                    clear()(clear_all)                       ⚠️ 见Bug#3
                    [:]= (建议修复方式)    迭代               ✅ 原子
TargetStats.        toggle_selected 写    worker 读           ✅ GIL原子
  is_running
TargetStats.        on_batch_complete 写  无                  ✅ 仅主线程
  统计字段           (信号槽，主线程)
PingWorker._stop    stop() 写             run() 读            ✅ GIL原子
_bg_workers 列表    append/remove         无                  ✅ 仅主线程
  (但closeEvent     退出时未清理          可能在运行          ⚠️ 见Bug#2
   不遍历)

结论:
  主要竞态集中在 self.targets 列表本身。GIL 保证不会内存损坏，
  但可能出现 RuntimeError（迭代中列表大小变化）。
  建议统一使用 in-place 切片赋值修改列表。

========================================
一、历史 Bug 修复情况（v1.1.1 → v1.1.2）

四、其他改进建议
========================================
  1. 缺少测试与 CI: expand_ip_range、_parse_ping_output 等纯函数
     适合用 pytest 覆盖
  2. is_running 语义过载: 同一字段既表示「是否启用」又驱动 status_text，
     建议拆分为 enabled 与运行状态
  3. host:port 解析重复: dialogs.py、_load_file()、dropEvent() 三处重复，
     应抽取公共函数（同时可修复 Bug #5）
  4. 无配置持久化: 间隔/并发数/超时等设置重启即丢失，可用 QSettings 保存
  5. 跨平台一致性: 可考虑用 ping3 等原生库替代系统 ping 子进程，减少进程
     开销并统一解析逻辑
  6. 序号列排序: 序号按行位置生成，排序后无意义，建议禁止排序或用固有 ID
